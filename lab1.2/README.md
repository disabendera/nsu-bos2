# Лабораторная работа 1.2.

## a. Синхронное ожидание потока (`thread_a.c`)
**Практика:**
Основной поток создаёт рабочий поток и вызывает `pthread_join()`. Из-за этого `main` ждёт, пока созданный поток завершится, и только после этого продолжает выполнение.

**Теория:**
По умолчанию поток создаётся в состоянии **Joinable**. После завершения такого потока часть служебной информации о нём сохраняется, пока другой поток не вызовет `pthread_join()`.

`pthread_join()` выполняет две основные задачи:
- ждёт завершения указанного потока;
- позволяет получить его возвращаемое значение и завершить обслуживание его ресурсов со стороны pthread-библиотеки.

Сам `pthread_join()` не освобождает память, которую поток выделил через `malloc()` — такую память нужно освобождать отдельно через `free()`.

---

## b. Возврат числа из потока (`thread_b.c`)
**Практика:**
Поток выделяет память под `int`, записывает туда число `42` и возвращает указатель. Основной поток получает этот указатель через `pthread_join()`, печатает значение и освобождает память через `free()`.

**Теория:**
Поточная функция имеет тип возврата `void *`, поэтому через неё можно вернуть указатель на данные.

Нельзя возвращать указатель на обычную локальную переменную потока:

```c
int value = 42;
return &value;
```

После завершения функции время жизни такой локальной переменной заканчивается, и использовать этот адрес больше нельзя.

Поэтому в нашей программе число хранится в куче через `malloc()`. Куча общая для всех потоков одного процесса, поэтому основной поток может прочитать это значение после `pthread_join()`.

---

## c. Возврат строки из потока (`thread_c.c`)
**Практика:**
Поток создаёт копию строки `"hello world"` через `strdup()` и возвращает указатель на неё. Основной поток получает указатель через `pthread_join()`, печатает строку и вызывает `free()`.

**Теория:**
`strdup()` выделяет память динамически, поэтому строка продолжает существовать после завершения поточной функции.

Важно различать два вида очистки:
- `pthread_join()` завершает работу с joinable-потоком;
- `free()` освобождает память, которую мы сами выделили через `malloc()` или `strdup()`.

---

## d. Создание потоков без `pthread_join()` (`thread_d.c`)
**Практика:**
Главный поток в цикле создаёт новые потоки. Каждый рабочий поток быстро завершается, но `pthread_join()` для него не вызывается.

**Теория:**
Так как потоки создаются как **Joinable**, после их завершения pthread-библиотека должна сохранять информацию, необходимую для возможного будущего `pthread_join()`.

Если постоянно создавать такие потоки и никогда их не `join`-ить, будут накапливаться ресурсы завершившихся потоков. В какой-то момент `pthread_create()` может перестать создавать новые потоки и вернуть ошибку, например `EAGAIN`.

В нашей программе стоит `sleep(15)`, поэтому ресурсы накапливаются очень медленно. Если убрать задержку, проблема проявится заметно быстрее.

## e. Отсоединение потока через `pthread_detach()` (`thread_e.c`)
**Практика:**
В начале поточной функции вызывается:

```c
pthread_detach(pthread_self());
```

После этого поток становится **Detached**.

**Теория:**
Для detached-потока не требуется вызывать `pthread_join()`. После его завершения pthread-библиотека сама освобождает связанные с ним служебные ресурсы.

Главное отличие:

- **Joinable** — поток можно ждать через `pthread_join()` и получить его результат;
- **Detached** — `pthread_join()` для него не используется, а ресурсы освобождаются автоматически после завершения.

Важно: detached-поток не означает «фоновый» поток. Он выполняется так же, как обычный поток; отличается только способ обработки его завершения.

В этом варианте поток сначала создаётся как joinable и только потом сам вызывает `pthread_detach()`.

## f. Создание Detached-потока через атрибуты (`thread_f.c`)
**Практика:**
Создаётся объект атрибутов:

```c
pthread_attr_t attr;
pthread_attr_init(&attr);
```

Затем указывается, что новый поток должен сразу быть detached:

```c
pthread_attr_setdetachstate(&attr, PTHREAD_CREATE_DETACHED);
```

После этого атрибуты передаются в `pthread_create()`.

**Теория:**
По поведению после завершения этот вариант похож на `pthread_detach()`: для потока не нужен `pthread_join()`, а его ресурсы освобождаются автоматически.

Разница в том, что здесь поток создаётся detached **сразу**, ещё в момент `pthread_create()`. Это удобнее, если заранее известно, что результат потока получать через `pthread_join()` не потребуется.

Кроме состояния `Joinable/Detached`, через `pthread_attr_t` можно задавать, например, размер стека потока и некоторые параметры планирования.

После того как атрибуты больше не нужны, обычно вызывают:

```c
pthread_attr_destroy(&attr);
```

В нашей программе после `while (1)` этот вызов фактически недостижим, потому что цикл бесконечный.

---

## Кратко: Joinable и Detached

| Joinable | Detached |
|---|---|
| Состояние по умолчанию | Нужно задать отдельно |
| Можно вызвать `pthread_join()` | `pthread_join()` не используется |
| Можно получить возвращаемое значение | Через `pthread_join()` результат получить нельзя |
| Ресурсы окончательно обслуживаются после `pthread_join()` | Ресурсы освобождаются автоматически после завершения |

Главное правило: если поток **Joinable**, его нужно в какой-то момент `pthread_join()`-ить. Если результат потока не нужен и ждать его отдельно не требуется, можно создать его **Detached**.

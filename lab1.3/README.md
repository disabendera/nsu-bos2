# Лабораторная работа 1.3

## a. Передача параметров в Joinable-поток (`thread_a.c`)

**Практика:**

В `main` создаётся локальная структура `struct task`, в неё записываются
число и строка. В `pthread_create()` передаётся адрес этой структуры
`&t`. Поток получает этот адрес через аргумент `void *arg`, приводит его
к `struct task *` и читает поля структуры.

После создания потока `main` вызывает `pthread_join()`, поэтому ждёт
завершения рабочего потока.

**Теория:**

Локальная структура `t` находится в стеке главного потока. У каждого
потока свой стек, но все потоки одного процесса работают в общем
адресном пространстве, поэтому один поток может обратиться к данным в
стеке другого потока, если получил правильный указатель.

Важно следить за **временем жизни** передаваемого объекта. В этой
программе это безопасно, потому что `main` вызывает `pthread_join()` и
не завершает работу раньше рабочего потока. Следовательно, структура `t`
продолжает существовать всё время, пока рабочий поток её использует.

В `pthread_create()` передаётся не копия структуры, а её адрес. Поэтому
рабочий поток обращается к той же структуре `t`, которая была создана в
`main`.

## b. Передача параметров в Detached-поток (`thread_b.c`)

**Практика:**

Поток создаётся сразу в состоянии `Detached` через:

``` c
pthread_attr_setdetachstate(&attr, PTHREAD_CREATE_DETACHED);
```

Структура для передачи параметров выделяется динамически:

``` c
t = malloc(sizeof(*t));
```

После успешного `pthread_create()` указатель на эту структуру передаётся
рабочему потоку. Когда данные больше не нужны, рабочий поток освобождает
память:

``` c
free(t);
```

**Теория:**

Detached-поток нельзя ожидать через `pthread_join()`, поэтому в этой
программе нет гарантии от `join`, что локальная переменная в стеке
`main` будет существовать достаточно долго.

Поэтому структура выделяется через `malloc()` в куче. Куча является
общей частью адресного пространства процесса, а выделенный объект
существует до тех пор, пока не будет вызван `free()`.

После успешного создания потока `main` больше не должен использовать или
освобождать `t`: владение этой памятью передаётся рабочему потоку.
Рабочий поток сначала использует структуру, а затем вызывает `free(t)`.
Если `main` освободит память раньше, рабочий поток может обратиться к
уже освобождённой памяти. Если память не освободит никто, возникнет
утечка памяти.

Важно различать ресурсы самого потока и память, выделенную программой
через `malloc()`. Состояние `Detached` позволяет pthread-библиотеке
автоматически освободить ресурсы завершившегося потока, но память,
выделенную через `malloc()`, программа всё равно должна освободить сама.

## Указатели внутри структуры

Поле:

``` c
char *text;
```

содержит не саму строку, а указатель на неё.

В нашей программе:

``` c
t->text = "detached hello";
```

указатель ссылается на строковый литерал, который существует всё время
работы процесса, поэтому отдельно копировать и освобождать эту строку не
нужно.

Если бы `text` указывал на локальный массив, время жизни которого могло
закончиться раньше рабочего потока, строку нужно было бы хранить в
памяти с подходящим временем жизни, например скопировать через
`strdup()`. В таком случае рабочий поток должен был бы освободить и
строку, и саму структуру.

------------------------------------------------------------------------

## Главное отличие двух вариантов

В варианте **a** структура находится в стеке `main`, а её время жизни
гарантируется тем, что `main` ждёт рабочий поток через `pthread_join()`.

В варианте **b** поток создаётся `Detached`, поэтому структура
выделяется в куче, а ответственность за её освобождение передаётся
рабочему потоку.

Главная идея лабораторной: при передаче указателя между потоками нужно
следить за тем, чтобы объект по этому адресу существовал всё время, пока
другой поток его использует.
